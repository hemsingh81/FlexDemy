# Story 7.3: Page Creation & Basic Content Blocks

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a tutor,
I want to insert Pages under any Topic or Sub-Topic and write their content using basic blocks (paragraph, sub-heading, lists, code),
So that I can put actual reading content under my outline, not just structure.

## Acceptance Criteria

1. **Given** the tutor's cursor is under a Topic or Sub-Topic heading **When** they type "/" and select "New Page" **Then** an `h4` structural marker is inserted carrying a title field and Confirmed/Unconfirmed badge, with the page body starting immediately below it in the same document (FR-13)
2. **Given** a Page exists **When** the tutor types "/" inside its body **Then** the menu offers Paragraph, Sub-heading, Bulleted list, Numbered list, and Code (with optional language) as insertable blocks, each compiling to Markdown `lib/markdown.ts` already renders (FR-25, FR-26 basic set, FR-27)
3. Page-body Sub-heading blocks render as `h5`/`h6`, never `h2`/`h3` — they must never collide with or be mistaken for a structural Topic/Sub-Topic heading in the document's heading tree (FR-26)
4. Blocks are reorderable by drag and by keyboard, convertible between compatible basic types (paragraph ↔ bullets ↔ numbered ↔ sub-heading), duplicable and deletable — structural headings are excluded from this conversion set (FR-29 basic types)
5. "Preview" toggles the page between edit and rendered-as-student view, and "Markdown" shows/permits direct editing of the raw body (FR-32)
6. Raw Markdown producing constructs the block editor can't represent is preserved verbatim as an uneditable "raw" block, never silently dropped (FR-33)

**Carried over from Story 7.2:** that story's AC #5 (FR-8, "move a Page to a different node") and its cascade-delete counts referencing pages/resources were explicitly deferred here since `Page` didn't exist yet — Task 7 below closes that gap. `Page` marker heading discipline (UX-DR1/AC #8 of Story 7.2) is also completed here for the first time.

Frontend: a new "Move page to…" button on a Page's `HeadingControls` cluster (`FolderInput` icon) opens a small `role="listbox"` picker -- built with the "picker over the course's Chapter/Topic/Sub-Topic outline" mechanism Task 7 names (not the drag-onto-the-rail alternative, a reasonable pick since `HeadingControls`' own drag machinery already exists for same-kind reorder and a second drag target on the rail would be a second interaction model for the same outcome). Component-level Page behavior (marker rendering, delete-impact message, delete/move-down calling the right service function, Preview/Markdown panel content and Close-discards-nothing) is covered in `CourseContentEditor.test.tsx` via a pre-built `ChapterDocumentDto` fixture containing a Page, driving the already-rendered controls with `userEvent` -- the same approach Story 7.2 used for Topic/Sub-Topic. The "New Page" slash-command's own `execute` handler (AD-11 sequencing) is exercised indirectly through its pure filtering logic (`getNearestPersistedOwner`, fully unit-tested) and through the backend `CreatePageAsync` tests; a full live-typing "/New Page" DOM integration test was not added, consistent with this codebase's established stance against fragile ProseMirror keystroke simulation (Story 7.1's own removed test, cited in this file's Story 7.2 section).
