## Story

As a student,
I want to open a Topic/Subtopic and see Drill-Down Level 1 with the ability to reveal deeper levels, against mock cached content,
so that the core player UX can be validated before real generation exists.

## Acceptance Criteria

1. **Given** mock Drill-Down content, **when** the player loads, **then** Level 1 shows first, **and** Level N+1 never shows before Level N is expanded. [Source: epics.md Story 3.1; PRD FR17]
2. **Given** `DrilldownPanel.tsx`, **when** built in this story, **then** its off-brand indigo/emerald Tailwind colors are swept to the real brand tokens (`ink-navy`/`citrus-amber`/`signal-green`) as part of this pass, not deferred. [Source: epics.md Story 3.1; UX-DR10]
3. **Given** a tutor-override exists for a level (mock), **when** rendered, **then** it displays in place of AI content. [Source: epics.md Story 3.1; PRD FR17]
4. **Given** the reading pane, **when** a student opens a Topic/Subtopic, **then** it shows that node's real content-tree shape (Chapter/Topic/Subtopic/ContentBlock, Epic 2's real entities) rather than the legacy Lesson/Module/Sentence model CoursePlayer currently reads from. [Source: this story's own scope decision -- see Dev Notes]
5. **And** data access goes through a stable hook/service interface (`useDrilldownContent()`) from the start, so Phase B swaps the mock implementation behind it without changing component code. [Source: epics.md Story 3.1]

- **Sizing risk, stated explicitly (mirrors epics.md's own treatment of Story 3.8's sizing risk):** Task 1+2 (bridging CoursePlayer's reading pane off the legacy Lesson/Module/Sentence model onto Epic 2's real content-tree shape) is the single largest task in this story and arguably in Epic 3's whole Phase A. - **Why the content-tree bridge is in scope for THIS story, not deferred:** epics.md's own AC text says "open a Topic/Subtopic" -- Epic 2's real entity names, not "Lesson." Every one of Stories 3.2-3.4's mock hooks (`useWays`, `useKeywordDefinition`, `useExercise`, `useCourseLifecycle`) and every one of Phase B's backend stories (3.5-3.9) also key off Topic/Subtopic ids. Doing this once, now, in the foundation story, is the whole point of this epic's own "write stories, analyze dependencies, minimize rework" pass.
- **What is explicitly NOT in scope, so this doesn't balloon into "rebuild the whole player":** the real backend student-facing content-tree READ endpoint (a course's `Chapter/Topic/Subtopic/ContentBlock` tree, published-only, no tutor-ownership check) does not exist yet -- `ContentTreeController` (Epic 2) is tutor-Draft-only. Epic 2 (Stories 2.1-2.10, all `done`) is the direct precedent for this epic's entire Phase A/Phase B structure and for the "stable hook/service interface from the start" pattern (Epic 2's `useFileUpload(courseId)`/`useCourseContentTree(courseId)` are the literal templates `useDrilldownContent(courseId, nodeId)` follows).
