## Verdict

**Mostly well-verified, with one real mischaracterization worth fixing.** Every library's existence, version currency, and license claim checks out (`@tiptap/react`/`core`/`starter-kit` 3.30.1 MIT, `@tiptap/markdown` MIT, HtmlSanitizer 9.1.973 MIT, SafeSVG BSD-3-Clause with its oddly-precise "4 stars/13 commits" confirmed accurate). The one genuine defect is backend **AD-28's characterization of `GHSA-43cp-6p3q-2pc4`**: the advisory is real, is about HtmlSanitizer, and is patched well before 9.1.973 — but it is **not** "about SVG+`foreignObject` XSS" as the spine states. It's about allowing `svg`/`math` as foreign content combined with certain raw-text elements (`iframe`, `noembed`, `xmp`, `title`, `noframes`, `style`, `noscript`); the advisory text never mentions `foreignObject`. This is a specific, plausible-sounding technical detail that appears asserted rather than checked. Frontend AD-9's "confirmed React 19-compatible" is a secondary, lower-severity overstatement — true for the packages actually used (core/react/starter-kit), but Tiptap's own tracker shows open React 19 gaps elsewhere in its ecosystem that the spine's flat "confirmed" doesn't hedge against.

## Summary of Findings by Severity

1. **[High]** Backend AD-28 mischaracterizes `GHSA-43cp-6p3q-2pc4` as being specifically about SVG `foreignObject` XSS. The real advisory (CVE-2023-44390) is about foreign-content (`svg`/`math`) combined with raw-text elements (`iframe`, `noembed`, `xmp`, `title`, `noframes`, `style`, `noscript`) bypassing sanitization — it never mentions `foreignObject`. Patch-timing claim ("now patched upstream," true as of 8.0.723/8.1.722-beta, both before 9.1.973) is accurate; only the attack-mechanism attribution is wrong. Fix: correct the citation's mechanism description, or state the `foreignObject`-denial rationale independent of this specific CVE.
2. **[Medium]** Frontend AD-9/Stack table's "confirmed React 19-compatible" overstates certainty for Tiptap 3.30.1. True for the core/react/starter-kit surface actually used, but Tiptap's own issue tracker shows unresolved React 19 gaps elsewhere in its ecosystem (Pro/UI Components, not used here) that a flat "confirmed" doesn't acknowledge.
3. **[Low]** Frontend AD-9's slash-menu citation omits that Tiptap's own official slash-commands example is itself labeled "experimental" on their site, even though the underlying `Suggestion` utility is stable.
4. **[Low / process]** Both files tag compound claims (version + license + framework-compat, or version + patch-status + attack-mechanism) with one undifferentiated "web-verified Aug 2026," which obscures which individual clause was actually checked. This is the same pattern that let finding #1 through — the CVE ID's real existence rode along with an unverified mechanism description under one confidence label.
5. **[Info/Confirmed-good]** Everything else checks out cleanly: `@tiptap/react`/`core`/`starter-kit` 3.30.1 MIT and genuinely current; no Tiptap v4 exists (3.x is correctly current, not stale); `@tiptap/markdown` is real, official, MIT, and — specifically re-checked per the task's prompt — confirmed **stable, not experimental/beta** via npm dist-tags and Tiptap's own release notes; the community `tiptap-markdown` deprecation claim holds; Tiptap's paid Pro Conversion extension is real; HtmlSanitizer 9.1.973 is real/current/MIT; no other HtmlSanitizer CVE was missed; SafeSVG's BSD-3-Clause license and "4 stars/13 commits" are accurate, not fabricated; no better SVG-sanitization alternative exists that should have been considered instead. AD-29 and the AD-17/AD-20 amendments contain no externally-checkable claims and were confirmed clean by inspection.
